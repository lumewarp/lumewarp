## 設計決定（★ = 需要 Andy 拍板，括號內是建議預設）

### D1 拿掉安裝層角色，改成「在 IAM group 裡」（Andy 已定）

- Lumewarp 不再有 superuser／installation admin 這種角色或旗標。
  - 移除 `users.is_superuser`、`Relation.SUPERUSER`、`installation` 資源、`ActorType.SUPERUSER_TOKEN`、UI 的 promote／demote。
- 安裝層操作只問一件事：這個人在不在 `LUMEWARP_ADMIN_GROUP`（例如 `lumewarp-admins`）裡。
  - 安裝層操作包括：建立／刪除 team、upstream／deployment／route、gateway token、使用者、設定 rollback、notifier。
- 誰回答「在不在 group 裡」，由授權後端決定；介面是 `check(user_id, "member", group:<name>)`：
  - `openfga`：model 加 `type group { relations define member: [user] }`，IAM 同步 group tuple；**即時生效**。
  - `http`：同一個 check 契約，`resource.type = "group"`。
  - `builtin`：沒有自己的 group 資料，改讀登入時 OIDC token 的 groups claim（`LUMEWARP_OIDC_GROUPS_CLAIM`，預設 `groups`），存在 session 上；下次登入或 session 過期（12 h）才更新。
- team 層（admin／member）不變，照舊走授權後端。
- **移除 bootstrap token**，改用 break-glass 密碼登入（Andy 2026-10-31）。CLI `bootstrap` 只負責建立 scope 與 gateway token。
  - 設定：
    - `LUMEWARP_BREAK_GLASS_PASSWORD_HASH`（argon2id，建議）；
    - 或 `LUMEWARP_BREAK_GLASS_PASSWORD`（明碼，只給 dev）；
    - CLI `lumewarp-control-plane hash-password` 產生 hash。
    - 兩者都沒設就停用，登入頁也不顯示這個選項。
  - 登入：UI 登入頁的「緊急登入」用帳號 `break-glass` 加密碼，換到一般的 cookie session（含 CSRF），不發 bearer token。
  - 權限：等同在 admin group 裡，能做所有安裝層操作，也能管理任何 team；不是 user，不能擁有 key 或 PAT。
  - session TTL 較短（預設 1 h，`LUMEWARP_BREAK_GLASS_SESSION_TTL_SECONDS`）。
  - 防護：
    - 常數時間比對；
    - 登入失敗速率限制（每 IP 加全域退避）；
    - 每次登入與每個操作都寫 audit，actor 為 `break_glass`；
    - metric `lumewarp_cp_break_glass_logins_total{result}`，並加告警規則：成功登入就告警；
    - 啟動時若啟用，log 一行 WARN。
  - 用途：初次安裝在 IdP 接好之前，或 IdP／授權後端故障時。group 判定在授權後端出錯時回 503，但 break-glass session 不受影響。
  - Helm：`controlPlane.breakGlass.passwordHashSecret`（引用既有 Secret），取代 `bootstrapToken`。
  - dev／e2e：`scripts/dev.sh` 設 dev 密碼；e2e 用 break-glass 完成初始設定，取代原本的 `ADMIN_TOKEN`，這樣 e2e-p1 不必起 IdP，也不用另寫 mock OIDC issuer。
- PAT：
  - 在 `builtin` 後端時不具 group 權限（PAT 沒有 claims，避免 group 被移除後留下後門），只能做 team 層與自己的事；
  - 在 `openfga`／`http` 後端時每次即時查 group，所以可以做 group 允許的操作。
- email 連結：帶 admin group 的登入不可用 email 連結到既有帳號，防止帳號接管。
- 連帶影響（W1 必做）：
  - CP 測試的 bootstrap fixture（約 171 處）改成「測試用授權後端 + 指定 group 的 session」；
  - e2e-p1 改用 break-glass session 取代 `ADMIN_TOKEN`，仍不需要 IdP；
  - `scripts/dev.sh` 一律起 Keycloak，dev realm 加 group `lumewarp-admins`（alice 在裡面）與 groups mapper。
- 這推翻 P2「IdP 只認證、不讀 groups」：`architecture.md`、`CLAUDE.md` 同步改寫。

### D2 router 改成 Rust 介面

- 新 crate `gateway/crates/lumewarp-router-api`：穩定、版本化的 trait，不依賴 gateway 內部型別。

  ```rust
  pub trait Strategy: Send + Sync + 'static {
      fn name(&self) -> &'static str;
      /// Called once per snapshot apply; parse params, precompute tables.
      fn configure(&mut self, route: &RouteInfo, params: &Params) -> Result<(), ConfigError>;
      /// Hot path: choose among eligible candidates. No I/O, no allocation in the common case.
      fn pick(&self, req: &RequestInfo, candidates: &Candidates<'_>, rng: &mut Rng) -> Option<usize>;
  }
  ```

  - `Candidates`：每個 deployment 的唯讀視圖，包含 name、weight、in_flight、latency EWMA、vLLM 負載（含是否過期）、health 和熔斷狀態（已過濾成 eligible）。
  - `RequestInfo`：model、team_id、key_id、白名單 header、估計輸入 token 數；**不含 prompt 內容**，避免 strategy 讀 prompt。
- 內建四種策略改寫成這個 trait 的實作，`Pool::pick` 改成呼叫 trait（enum dispatch 或 `&dyn`，以 bench 決定）；行為不變，既有測試全過。
- （W1 已照此實作；之後由 `docs/plans/model-catalog.md` 的策略 schema 取代 `custom_strategy`。）proto：`ModelRoute` 加 `custom_strategy`（名稱）與 `strategy_params`（`google.protobuf.Struct`）；capability `strategy:<name>`，gateway Hello 回報自己編進去的策略，不認得的名稱 NACK `UNSUPPORTED_FEATURE`。
- **自訂策略怎麼進 gateway**（Andy 同意建議）：編譯期註冊。使用者在 `gateway/strategies/<name>/` 寫一個 crate，實作 trait 並以 `inventory`／linkme 註冊，重新 build gateway（或用 cargo feature 選擇要編進哪些）。熱路徑零額外成本，符合「效能主張要有數字」。
  - 替代：WASM（不用重編 gateway，但每請求要多一次 sandbox 呼叫，p99 有成本）；動態 `.so`（ABI 不穩，不建議）。
- **Python router plugin 整個移除**（Andy 已定），拿掉 `lumewarp.router` entry point：編譯期改權重的需求改成「Rust 策略 + params」，或外部腳本呼叫 CP API 調權重。`auth`／`notifier` plugin 不受影響。
- 「共用 API 介面」雙軌：
  - Rust trait 是策略的程式介面；
  - CP 的 routing API（route 設定 `custom_strategy` + params、deployment 權重 PATCH）是外部系統動態調整的介面。
- skill：repo 內 `.claude/skills/port-router-to-rust/`，同時放到 `~/.agents` 可讀的位置，讓 senpi／Codex 也能用。輸入 Python `RouterPolicyPlugin`，輸出：
  1. 策略 crate；
  2. 單元測試（含與 Python 版的對照表測試）；
  3. bench 指令；
  4. 一個範例：把 `CheapestFirstRouter` 轉成 `cheapest-first` 策略。
- 文件：`docs/router-strategies.md`，寫 trait 契約、熱路徑規則（不可 I/O、不可阻塞、不可讀 prompt）、params schema 與 bench 要求。

### D3 DB 不存明碼憑證

- 已合格：key／PAT／gateway token／session／CSRF／OIDC state（sha256；這些 token 是 256-bit 隨機值，快速 hash 足夠，文件說明理由）。
- 修正 1：OIDC `nonce`、`code_verifier` 不再進 DB，改放在用伺服器金鑰加密的 cookie（AES-GCM）。
  - 金鑰來源：`LUMEWARP_SECRET_KEY`；未設定時啟動拒絕開 SSO。
  - 拿掉 `oidc_login_states` 這兩欄（新 migration）。
- 修正 2：notifier channel 的 webhook URL 改成跟 upstream 一樣只存 env 名稱（`url_ref`），或用 `LUMEWARP_SECRET_KEY` 加密存放。
  - ★ 建議用 env ref，與 upstream 一致、最簡單；若之後 UI 要能貼上 webhook／上游 key，再引入加密欄位。
- 修正 3：audit redaction 改成 allowlist（每個 action 宣告可記的欄位），`last_error` 類自由文字欄位只存錯誤類別。
- 守門測試：
  - schema 掃描：每個 Text／String／JSONB 欄位必須列在「非機密」清單或使用 hash／加密型別，新增欄位沒分類就失敗；
  - e2e 跑完後 `pg_dump` 不得出現 `lw-`／`lwp-`／`lwg-` 開頭的完整 token、nonce 或 code_verifier 樣式字串。

### D4 一般使用者自助

- 誰能登入：任何 IdP 使用者（JIT，零權限）；看得到哪些 team 由 team 成員關係決定（builtin 或外部 IAM）。
- 「自己權限的 key」= 自己是 member 的 team 裡、owner 是自己的 key。
- API 已大致具備；補齊：
  - `GET /users/me` 回傳每個 team 的可用模型、限制與剩餘預算，讓使用者知道能拿 key 做什麼；
  - 建立 key 時可設到期日；team 可設 `max_keys_per_member` 與「member key 最長效期」；
  - ★ **輪替寬限**（建議：要）：rotate 後舊 hash 在 `grace_seconds`（預設 0，上限 24 h）內仍有效，snapshot 帶兩個 hash，到期由 CP 推 delta 移除；
  - 建立／輪替有速率限制，並寫 audit。
- UI：一般使用者首頁是「我的 key」，涵蓋各 team 的 key、建立、輪替（顯示一次 secret）、撤銷、自己的用量；管理頁只對 installation admin 或 team admin 顯示。
- ★ team 成員關係要不要也由 IdP group 對應（group → team 自動加入）？建議**這一版不做**，維持 builtin／外部 IAM 管 team 成員，避免兩套來源打架。
