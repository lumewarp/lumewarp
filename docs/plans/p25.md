## 設計決定（★ = 需要 Andy 拍板，括號內是建議預設）

### D2 轉換 router 的 skill

- skill 放在 repo 內 `.claude/skills/port-router-to-rust/`，同時放到 `~/.agents` 可讀的位置，讓其他 agent 也能用。
- 輸入：使用者既有的 Python router policy。輸出：
  1. 策略 crate，用 `register!` 和 `Configure<P, M>` 宣告 params 與成員欄位（介面見 `docs/router-strategies.md`，參考實作是 `gateway/strategies/priority-failover`）；
  2. 單元測試，含與 Python 版的對照表測試；
  3. bench 指令；
  4. 一個範例：把 `CheapestFirstRouter` 轉成 `cheapest-first` 策略。

### D3 DB 不存明碼憑證

- 已合格：key／PAT／gateway token／session／CSRF／OIDC state（sha256；這些 token 是 256-bit 隨機值，快速 hash 足夠，文件說明理由）。
- 修正 1：OIDC `nonce`、`code_verifier` 不再進 DB，改放在用伺服器金鑰加密的 cookie（AES-GCM）。
  - 金鑰來源：`LUMEWARP_SECRET_KEY`；未設定時啟動拒絕開 SSO。
  - 拿掉 `oidc_login_states` 這兩欄（新 migration）。
- 修正 2：notifier channel 的 webhook URL 改成跟 upstream 一樣只存 env 名稱（`url_ref`），或用 `LUMEWARP_SECRET_KEY` 加密存放。
  - ★ 建議用 env ref，與 upstream 一致、最簡單；若之後 UI 要能貼上 webhook／上游 key，再引入加密欄位。
- 修正 3：audit redaction 改成 allowlist（每個 action 宣告可記的欄位），`last_error` 類自由文字欄位只存錯誤類別。
- 守門測試：
  - schema 掃描：每個 Text／String／JSONB 欄位必須列在「非機密」清單或使用 hash／加密型別，新增欄位沒分類就失敗；
  - e2e 跑完後 `pg_dump` 不得出現 `lw-`／`lwp-`／`lwg-` 開頭的完整 token、nonce 或 code_verifier 樣式字串。

### D4 一般使用者自助

- 誰能登入：任何 IdP 使用者（JIT，零權限）；看得到哪些 team 由 team 成員關係決定（builtin 或外部 IAM）。
- 「自己權限的 key」= 自己是 member 的 team 裡、owner 是自己的 key。
- API 已大致具備；補齊：
  - `GET /users/me` 回傳每個 team 的可用模型、限制與剩餘預算，讓使用者知道能拿 key 做什麼；
  - 建立 key 時可設到期日；team 可設 `max_keys_per_member` 與「member key 最長效期」；
  - ★ **輪替寬限**（建議：要）：rotate 後舊 hash 在 `grace_seconds`（預設 0，上限 24 h）內仍有效，snapshot 帶兩個 hash，到期由 CP 推 delta 移除；
  - 建立／輪替有速率限制，並寫 audit。
- UI：一般使用者首頁是「我的 key」，涵蓋各 team 的 key、建立、輪替（顯示一次 secret）、撤銷、自己的用量；管理頁只對 installation admin 或 team admin 顯示。
- ★ team 成員關係要不要也由 IdP group 對應（group → team 自動加入）？建議**這一版不做**，維持 builtin／外部 IAM 管 team 成員，避免兩套來源打架。
